# Демонстрационный стенд для диплома (макет)

> Задача — не оборудовать гараж, а показать работающий комплекс на защите.
> Принцип: **реально только то, что составляет новизну. Остальное имитируется
> программно на тех же MQTT-топиках.** Для регулятора, Astra и комиссии стенд
> неотличим от реального объекта.

## 1. Что РЕАЛЬНОЕ (ядро новизны, имитировать нельзя)

| Железо | Что демонстрирует | Ссылка на раздел диплома |
|---|---|---|
| **Pi4 (сервер)** | Mosquitto, InfluxDB (история), HA, регулятор (автоматика), Astra Core, Piper TTS, policy engine МФА | Глава 3 |
| **Pi5 + Coral M.2** | BlazeFace 28мс / InsightFace, Whisper small ru, конвейер FaceID 180мс | Глава 4, бенчмарки 29x/31x |
| Камера (обычная/USB) | Живое распознавание лица при комиссии | 4.1 |
| USB-микрофон + колонка | Голос: wake → команда → ответ Astra | 3.3 |
| R503 (есть) | Приложить палец при комиссии — тактильное демо | 4.3 |

## 2. Что ИМИТИРУЕТСЯ (симуляторы вместо железа)

| Реальный узел | Симулятор | MQTT-топики (без изменений!) |
|---|---|---|
| ESP32 + BME280 (климат) | `garage_simulator.py` | `garage/climate/temp\|humidity\|pressure` |
| ESP32 + MQ-7 (газ) | сценарий `gas_leak` | `garage/gas/co` |
| ESP32 + BH1750 (свет) | параметр `lux` | `garage/light/lux` |
| LD2450 радар | `person in` → JSON целей как у LD2450 | `garage/security/radar` |
| Ворота | `gate open\|close` | `garage/gate/state` |
| Замок | реле Pi4 + сервопривод SG90 или LED (опция) | `garage/access/granted` |
| Вытяжка | реле Pi4 + USB-вентилятор 5В (опция) | `garage/actuator/fan` |
| Сирена | buzzer на GPIO (опция, 1€) | `garage/alarm` |
| NFC + PIN | символический RC522/клавиатура ИЛИ MQTT-публикация от «виртуального узла» | `garage/access/nfc/result`, `garage/access/pin/result` |

**Экономия против полного комплекта: ~230-260€ → 10-15€** (серво+buzzer+вентилятор
для визуальности — полностью опционально).

## 3. Симулятор

`services/simulators/garage_simulator.py` — физическая модель гаража,
публикует телеметрию в боевые топики. Управление сценариями:

```bash
pip install -r services/simulators/requirements.txt

# Сценарий одним запуском
python3 garage_simulator.py --broker 10.0.0.1 scenario gas_leak

# Интерактив (для защиты - из ноутбука по GarageNet)
python3 garage_simulator.py --broker 192.168.4.1 interactive
sim> gas up        # CO пополз, через ~45 сек тревога на Pi4
sim> person in     # радар "увидел", свет, ворота
sim> temp -8       # похолодание, антифриз-алерт
```

Сценарии: `normal`, `gas_leak` (CO 5→120ppm), `person` (радар+ворота+свет),
`night` (похолодание к −8), `cold` (антифриз-алерт).

## 4. Сценарий демонстрации на защите (~5 мин)

| # | Действие | Что происходит | Что говорит комиссия |
|---|---|---|---|
| 1 | Лог MQTT на проекторе (`mosquitto_sub -v`) | Телеметрия всех узлов в шине | «Все данные проходят через единую шину MQTT» |
| 2 | sim> `person in` | Радар → свет → камера → FaceID → Astra: «Здравствуйте, Влад» | «Распознавание выполнено на нейроускорителе за 180 мс» |
| 3 | Приложить палец к R503 | garage/access/granted, замок | «Мультимодальная биометрия, второй фактор» |
| 4 | sim> `gas up` | CO растёт → >50ppm → вытяжка+сирена+Astra предупреждает | «Аварийная логика срабатывает независимо от ассистента» |
| 5 | «Астра, выключи свет» | Pi5 Whisper → Pi4 интент → реле → «Готово» | «Полностью офлайн STT+NLU+TTS, без облака» |
| 6 | Показать логи MQTT | Все сообщения в шине | «Единый протокол, узлы независимы» |

Резервный вариант демо (если что-то падает): запись видео работающей системы +
`mosquitto_sub -t 'garage/#' -v` на проекторе — шина не может «сломаться наполовину».

## 5. Питание и транспортировка стенда

- Один сетевой фильтр: Pi4 + Pi5 + монитор
- Pi4↔Pi5 — патч-корд, ноутбук комиссии — в GarageNet (WiFi AP) или локальная сеть вуза
- Коробка/папка для переноски: два Pi в корпусах, камера, микрофон, R503, провода
- Всё разворачивается из git: `docker compose up -d` + скрипты из `scripts/`

## 6. Что писать в дипломе про стенд

В разделе «Практическая реализация»: «исполнительные механизмы и часть датчиков
представлены имитаторами на уровне протокола MQTT — симулятор воспроизводит
физические характеристики узлов (инерционность нагрева, ползучесть концентрации CO,
траектории целей радара), что позволяет проверять логику комплекса без натурных
испытаний». Это корректная постановка: **имитация на уровне интерфейсов** —
стандартная практика (hardware-in-the-loop наоборот, software-in-the-loop),
и это отдельный плюс к работе: симулятор полезен и для разработки реального гаража.
