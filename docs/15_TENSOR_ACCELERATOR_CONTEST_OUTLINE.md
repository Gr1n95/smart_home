**Тема:** «Принципы работы тензорных ускорителей и экспериментальная оценка их эффективности на примере полного конвейера детекции лиц на Raspberry Pi 5».

> Актуальная структура с учётом имеющегося стенда: **Coral M.2 по PCIe, без USB-ускорителя и без прибора для измерения энергии**. Числа в скобках — план объёма, не номера страниц. Разделы результатов и заключение заполняются только после собственных измерений. См. [рукопись](./16_TENSOR_ACCELERATION_MANUSCRIPT.md) и [экспериментальный протокол](../research/tensor_acceleration/PROTOCOL.md).

## Как уложиться в лимит до 65 страниц

| Часть | План, с. |
|---|---:|
| Титульный лист, содержание, аннотация | 2 |
| Введение | 4 |
| Глава 1 | 17 |
| Глава 2 | 14 |
| Глава 3 | 18 |
| Заключение | 3 |
| Источники | 4 |
| Приложения | 3 |
| **Всего** | **65** |

Сумма подпунктов каждой главы соответствует её бюджету: **17 + 14 + 18 = 49 страниц**; на остальное остаётся **16 страниц**. Одну страницу из бывшей методики измерения энергии перенесли в статистическую обработку (2.4). Если титульный лист, литература или приложения не входят в лимит, бюджет после изучения регламента надо скорректировать. Реальные номера страниц появятся только после вёрстки.

## Что исключено и что остаётся научным ядром

1. **Энергопотребление — исключено из исследовательских показателей.** Не будет трёхкритериального анализа, джоулей на кадр, «энергоэффективности» или расчётов по паспортным ваттам. В пп. 1.8 и 2.6 остаются температура, частота CPU и признаки троттлинга как **контроль условий** для корректного сравнения времени; эти данные нельзя выдавать за измерение энергии Coral.
2. **USB — исключён из эксперимента.** Исследуется Coral M.2 на PCIe. Пункт 1.4 рассматривает вычислительные/памятные ограничения и обмен с *имеющимся* PCIe-устройством. Верхняя оценка скорости PCIe и Roofline — не замер внутренних транзакций закрытого чипа. Утверждений «PCIe быстрее USB в N раз» в работе не будет.
3. **Технико-экономический расчёт — не самостоятельная цель.** Пункт 3.8 содержит краткие рекомендации по выбору CPU/TPU **по измеренной задержке, качеству и ограничениям модели**, а не рекламное сравнение цен или проектирование умного гаража.
4. **Главная проверка — полный путь детекции лиц:** одинаковый кадр → предобработка → модель → боксы/постобработка. `invoke()` измеряется отдельно как диагностический этап. Качество сравнивается на размеченных кадрах (AP@0.5, recall, ложные срабатывания); без разметки не утверждать, что точность сохранена. С одной парой детекторов и без проверенных вариантов порога/сети нельзя обещать полноценную кривую Парето «точность–задержка»: п. 3.4 может быть проверкой сохранности качества **при измеренном выигрыше по задержке**.
5. **Ablation — с оговорками.** `CPU float ↔ CPU INT8` показывает эффект квантования только при сопоставимых архитектуре и весах; `CPU INT8 ↔ TPU INT8` — эффект смены исполнения вместе с накладными расходами. Долю влияния fallback нельзя достоверно получить из одного лишь числа делегированных операторов или вычитанием двух полных задержек. Если подходящего float-контроля/вариантов графа нет, назвать сравнение наблюдательным и ограничить выводы, а не сочинять отдельный вклад.
6. **Инструмент пока неполон.** [Микробенчмарк](../research/tensor_acceleration/benchmark.py) записывает `set/invoke/get`; он **не** выполняет полный конвейер и не визуализирует сегменты CPU/TPU. Эти функции ещё предстоит разработать для пунктов 2.7, 3.1 и 3.3. Старые ориентировочные «29×»/«28 мс» не являются результатами.

**Ближайший практический шаг:** подтвердить доступ к Pi 5 + Coral и к разрешённым к использованию размеченным изображениям. Затем реализовать/проверить полный детектор, провести пилотные измерения, зафиксировать объём основного опыта и заполнять главу 3 собственными данными.
